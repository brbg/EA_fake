## 完成事项

### 步骤 4：工具从 5 个扩到 19 个

此前只有「建项目 / 生成架构 / 改模型 / 体检 / 优化」5 个工具，平台其余绝大多数用户操作
——代码生成、若依、文档、版本、研发管理 CRUD、AI 评审——**都无法通过对话完成**。

新增 14 个：`rename_project` / `delete_project` / `review_model` / `generate_code` /
`generate_ruoyi_module` / `reverse_code` / `generate_document` / `version_control` /
`remember` / `dev_list` / `dev_create` / `dev_update` / `dev_delete` / `dev_ai_generate`。

**研发管理用 5 个通用工具覆盖 4 类实体 × CRUD + AI 生成**（否则要 17 个工具）：
`kind` 枚举 + `fields` 白名单过滤，传该类型不支持的字段时**明确拒绝**而不是静默无操作。

**破坏性操作守卫**（`delete_project` / `dev_delete` / `version_control:restore`）：
不带 `confirm` 时**零副作用**，只返回待确认信息；模型须先向用户复述、得到肯定答复后
再以 `confirm=true` 重调。删项目前把模型 JSON 落一份到 `data/deleted/`；回滚前先存快照。

**预算上调**：`max_steps` 6→12、结果截断 4000→8000、`max_tokens` 2048→4096
（工具变多、链路变长，且多工具后的中文总结会被截断）。

**明确不在列**：纯前端操作（撤销/重做/清空/导出图片/手工拖拽）没有后端接口，
原理上无法由对话触发。

## 测试抓到的真 bug

**`version_control` 用了 `m.versions`，而 `SimpleModel` 的属性名是 `m.history`**
（`save_version` 追加到 `history`）。表现为「保存成功但列表仍是 0 个」——
是新增的 `test_agent_tools.py` 抓出来的，不是靠读代码发现的。

另外两条失败是**我测试自己写错了**（stub 的返回顺序、给 testcase 传了它不支持的
`status` 字段），已修正——后者恰好证明了字段白名单在正常工作。
