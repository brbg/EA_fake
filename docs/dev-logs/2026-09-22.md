### 3. AI 生成质量保障 7 项（本次主体）

设计见 [docs/superpowers/specs/2026-09-22-ai-quality-design.md](../superpowers/specs/2026-09-22-ai-quality-design.md)。核心是补上最缺的那一环——**校验器只报告、从不回喂模型**。

- **校验-回喂修复循环**：一键生成后自动跑一轮（校验 → 按图分组回喂错误 → 重校验）。`applied` 的判据是「有没有真的改动」而非「模型有没有提出」。
- **Best-of-N 采样择优**：默认 3 次采样，用**确定性校验器**打分选最好的；第 1 个满分就早退、第 1 次就失败立刻降级。
- **确定性打分器**：error 12 / warning 4.5 / minor 1.5，加覆盖度与结构惩罚，clamp 到 0–100。**永不接受 model 对象**——两个校验器内部会调 LLM，踩上去会让打分不可复现。
- **闭合 fail-open 口子**：UML 未知元素类型、ER 字段类型改为闭合白名单回落（原 `capitalize()` / `.upper()` 直接放行）；`ELEMENT_TYPES['uml']` 补 `'Enum'`；ArchiMate 布局器补同名去重。
- **产物自检提到生产侧**：`java_lint` / `vue_lint` 从测试搬到 [code_lint.py](../../EA_fake/ea-webapp/backend/code_lint.py)，测试改为 import → 从此锁的是生产实现。自检在路由层收集告警，永不 raise。
- **跨图命名对齐**：高置信变形（去表名前缀、同义词、单复数差异）自动统一到 UML 名；真正不同的只进健康度报告；中文名一律不动；跨命名约定视为设计使然。
- **诚实计数**：`applied_ops` 从「LLM 声称步数」改成「真实生效步数」，新增 `claimed_ops` / `discarded`（含原因），前端文案同步为「生效 X / 模型提出 Y 步 + 未生效明细」。

## 过程中发现并修掉的真问题

1. **`_apply_er_edits` 浅拷贝别名缺陷**：`[dict(e) for e in erEntities]` 浅拷贝，`add_field` 的 `target['fields'].append(...)` 会**原地改掉调用方的模型**（实测：调用方 fields 从 1 变 2）。这让「报告说 0 步生效、模型其实已被改」成为可能，直接摧毁诚实计数的语义。
2. **空画布提示被当成可修问题**：`review_archimate_model` 把「画布为空」也报成 warning，导致一个只有 ER 的健康模型被判定成「有问题」并白花一次 LLM 调用。修复：修复循环与打分器都滤掉 `type=='empty'`（打分器那边还顺带消掉了与覆盖度惩罚的重复扣分）。
3. **`_singular` 把 `sys` 单数化成 `sy`**：`name_key('sys_user')` 得到 `'sy_user'`，前缀再也匹配不上。修复：末尾裸 `s` 的词干要求 ≥3 字符，且剥表名前缀改在单数化**之前**、按 token 做。
4. **`@app.route` 装饰器被挂到辅助函数上**：插入 `_edit_counts` 时它落到了路由装饰器与视图函数之间，Flask 把 URL 路由到了辅助函数上（报「unexpected keyword argument 'model_id'」）。由接口契约测试抓到。
5. **跨图命名报告噪音**：`ArchiMate「OrderService」与 UML 类「Order」` —— 角色后缀是三图之间的惯用对应，报出来会淹没真正该看的问题。已加抑制规则。

## 遗留 / 待办
