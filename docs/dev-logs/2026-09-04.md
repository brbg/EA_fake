**修复「代码生成 → 反向」round-trip 不一致：新增 POJO 纯类（往返保真）输出，完整保留 UML 属性/方法/继承。**

## 完成事项

### 1. 问题根因
- UML 类图 → 生成代码 → 粘贴到「代码反向」→ 反向出的图与原图不一致（属性/方法丢失）。
- 根因一：本地 entity 模板（`generateEntityCode`）只遍历 `attributes` 生成字段，**从不输出 `methods`** → 方法在代码生成阶段就丢了。
- 根因二：后端 `_describe_model_for_code` 的 UML 分支**只列元素、不列关系**，且前端 AI 生成 payload **没传 UML connections** → AI 生成时根本感知不到继承/实现关系。

### 2. 修复：UML 源新增「POJO 纯类（往返保真）」输出
- **UI**：代码生成输出下拉（UML 源时）新增「POJO 纯类（往返保真）」（[App.vue](../../EA_fake/ea-webapp/src/App.vue)）。
- **本地模板 `generatePojoCode(language)`**（Java / Python / TS / C#）：遍历类+连接，生成纯类代码，完整保留——
  - 全部属性（`- name: String` → 可见性+类型字段，复用 `parseUmlAttr` + `mapTypeToJava/Django?/TypeScript/CSharp`）
  - 全部方法签名（`+ 方法名(参数: 类型): 返回类型` → public/private 方法）
  - 继承/实现（`inheritance` 连接 → `extends`；`realization` → `implements`；接口 → `interface`）
  - 关联/聚合/组合 → 成员引用字段
- **AI 生成配合**：
  - 前端 AI payload 补传 `connections`
  - 后端 `_describe_model_for_code` 补 `uml_connections` 参数，UML 分支输出「类 A 继承 类 B」等关系
  - `code_system_prompt` 加 `output_type=='pojo'` 分支：要求生成纯领域类、完整保留所有字段/方法/继承、不得分层脚手架

### 2. Java Entity 生成升级为 Spring-Data-JPA 实体
- 用户规格：依据 UML 图生成全套 Spring-Data-JPA 实体——实体只做数据载体（无 save/update/拷贝方法）、关联 `fetch=FetchType.LAZY` 按多重度写 ManyToOne/OneToMany/OneToOne 且 `mappedBy` 正确、主键 `IDENTITY`、`javax.persistence` 注解、`toString` 避免关联递归、持久化交 Repository。
- 实测发现：AI 启用时 entity 生成**走后端 AI**（前端本地模板只是回退）。故改两处——
  - 后端 [prompts.py](../../EA_fake/ea-webapp/backend/prompts.py) `code_system_prompt`：`entity + java` 分支加入上述规格（javax、IDENTITY、LAZY、mappedBy、防递归 toString、无业务方法）。
  - 前端 [App.vue](../../EA_fake/ea-webapp/src/App.vue) 本地回退 `generateJpaEntitiesJava()`：javax/IDENTITY + 按 UML association/composition/aggregation + cardinality 生成双向关联（ManyToOne/OneToMany/OneToOne + @JoinColumn/@JoinTable、mappedBy），scalar 字段 `toString` 只拼标量防递归。
- 实测（Edge headless + AI）：单类输出含 `javax/IDENTITY/@Column/getter-setter/toString 防递归/无业务方法` ✓；两同类关联输出曾含 `@ManyToOne/@OneToMany/LAZY/mappedBy` ✓。

### 4. JPA 贫血实体模式双向闭环 + UML_META（一次性全做）
- 需求：图↔Java 往返一致且闭环（save/拷贝方法不双向循环污染）。按用户 4+8 点规则落地：
  - **开关**：全局 `jpaAnemic`（sessionStorage，默认开），代码生成页顶部 checkbox，控制正向生成与反向。
  - **实体识别**：命名启发（后缀排除 Service/Controller/Repository/Mapper/DTO/VO/Converter/Helper/Util/Api/Client/Handler/Factory/Proxy）；反向以 **@Entity 注解优先**于命名。
  - **正向 UML→Java(entity)**：只「实体」类生成 @Entity（贫血=仅字段+getter/setter+防递归 toString，不含 UML 方法/save/拷贝）；被继承父类生成 @MappedSuperclass；关闭开关则所有类原样生成（含方法存根）。每类写 `// UML_META:{x,y,type,rel:[{kind,to,card}]}` 注释（布局/菱形/多重度等 Java 无法表达的绘图语义）。POJO 生成同样写入 Uml_META。
  - **反向 Java→UML（code_reverse_system_prompt 增强 + app.py）**：带 @Entity 类只取字段、不画 save/拷贝/构造/getter/setter；@ManyToOne/@OneToMany/@OneToOne/@JoinColumn/@JoinTable → association/composition + cardinality；implements → realization；父类/@MappedSuperclass → inheritance；有 UML_META 时还原 x/y 与连线（真实源码优先、过期元注释不采信）；无元注释禁止脑补父接口(JpaRepository)方法/构造函数/菱形；布局丢失返回 notice 提示。关系 type 统一小写。
- 实测（本地 AI smoke）：anemic=true 实体 methods 空（saveOrder/copyFrom 未画出）、false 全部画出；@ManyToOne 还原出 Order→Customer 关联连线。✓
