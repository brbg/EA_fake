## 一、若依产物补成「开箱可用」

### 1. 先拿事实，不猜

拉官方工程核对（`gitee.com/y_project/RuoYi-Vue`）：**RuoYi-Vue 3.9.2 / Spring Boot 4.1.0 / Java 17**。
这三项和我原先的假设**都不同**（原以为 3.9.0、Spring Boot 3）——pom 的 `<parent>` 坐标必须与目标工程一致，
猜错 Maven 直接解析失败，所以这一步不能省。

产物只用到 `com.ruoyi.common.*` 一类，**全部由 `ruoyi-common` 传递带来**，所以模块 pom 只需要这一个依赖。

### 2. 生成 `pom.xml` + `INTEGRATION.md`（补上最卡的缺口）

此前产出是「模块源码树」，Maven 模块要用户自己建，README 只写「确认该模块已被 ruoyi-admin 依赖」——
拖进工程根本编译不了。

**集成是三处编辑，不是两处**——第三处是真编译才发现的：根 pom 的 `<dependencyManagement>` 只为官方
那几个模块管了版本，新模块不加这条会报 `'dependencies.dependency.version' for com.ruoyi:<模块>:jar is missing`。
已做成可粘贴片段写进 `INTEGRATION.md`。

新增配置项 `ruoyiVersion`（默认 3.9.2，格式校验），前端若依配置面板可改。

### 3. 复合主键改为**联合主键实现**（不再降级）

此前只把第一个 `isPrimary` 当主键、其余降级为普通列，**而 DDL 却按复合主键写全**——代码与 DDL 不一致，
中间表这类必中的表生成的 CRUD 是错的，只留一句「需手工调整」。

改为：所有主键列保持主键，Mapper/Service 多参数、Controller 两段路径、XML 组合键 where、
**不生成批量删除**（复合主键的批量删语义不成立）、**不加 auto_increment**（MySQL 只允许一个且须在索引首列）。

**过程中发现一个编译期看不出的坑**：多参数方法不加 `@Param` 时，MyBatis 只认 `param1/param2`/`arg0/arg1`；
想用 `#{orderId}` 得**同时**满足「编译带 `-parameters`」和「`useActualParamName=true`」——
两个隐式条件任一不成立就在**运行时**报 `Parameter 'orderId' not found`。已逐个加注解堵死。

单主键产物**逐字未变**（加了回归断言锁住）。

### 5. 被真库否掉的一个「我以为的 bug」

复合主键表 DDL 里有句 `auto_increment=1`，而该表根本没有自增列。我判定这是 bug、准备去改。
真库跑下来：**不报错，MySQL 直接忽略**（`SHOW CREATE TABLE` 里没这个子句）。

→ **验证的价值不只是证明对，也包括证明「你担心的不是问题」**。幸好是跑了而不是照着怀疑改。

### 6. 实测踩到、已写进 `INTEGRATION.md` 的两个坑

1. **导入 SQL 必须 `--default-character-set=utf8mb4`** —— SQL 里有中文表注释与菜单名，客户端字符集不对会报 `Data too long for column`
2. **要导入跑过官方 `sql/ry_*.sql` 的库** —— 生成的 SQL 会 insert 到 `sys_menu`，空库会报 `Table 'sys_menu' doesn't exist`
